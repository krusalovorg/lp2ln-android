# LP2LN Android

Android-клиент LP2LN со встроенным Rust-узлом и интерфейсом Jetpack Compose.

## Возможности

- Разделы «Файлы» и «Сеть», поиск по имени, меню действий, настройка bootstrap.
- Выбор документов через Android Storage Access Framework, до 100 МиБ.
- Шифрование блоков XChaCha20Poly1305 и отдельное шифрование манифеста с ключом файла.
- Передача блоков через BlockTransferService. Статус «В сети» появляется только после
  PushAck для всех блоков и манифеста от одного и того же удалённого узла.
- Локальный индекс в приватной директории приложения, повтор неудачной передачи.
- Сохранение расшифрованной копии через системный диалог Android.
- Постоянная БД и Peer ID, TCP/UDP, LAN discovery, статистика соединений.
- DNS-имена bootstrap разрешаются в IPv4 на нативной стороне.

## Интерфейс в Android Studio

Откройте MainActivity.kt и выберите Split / Design → Build & Refresh.
Превью FilesPreview и NetworkPreview работают без сети на тестовых данных.

## Сборка

Нужны Android SDK/NDK, cargo-ndk и toolchain из rust/rust-toolchain.toml.

```powershell
.\gradlew.bat assembleDebug
# Быстрая сборка для физического телефона ARM64:
.\gradlew.bat assembleDebug -PrustAbis=arm64-v8a
.\gradlew.bat installDebug -PrustAbis=arm64-v8a
# Только Kotlin; использует уже собранные .so, если они есть:
.\gradlew.bat testDebugUnitTest -PskipRustBuild
# Важно запускать Cargo из rust/, где применяется toolchain:
cd rust
cargo test --lib -- --test-threads=1
```

В rust/.cargo/config.toml может быть настроена локальная привязка к основному
репозиторию LP2LN. Без неё Cargo использует закреплённую Git-ревизию из Cargo.toml.

Адрес сервера не хранится в исходниках. Для своей сборки задайте переменную
окружения LP2LN_BOOTSTRAP либо Gradle-параметр lp2lnBootstrap. Без него адрес
вводится в разделе «Сеть». Приватные конфигурации развёртывания находятся в
deployment/private/ и исключены из Git. Адрес в готовом APK не является секретом:
его можно прочитать в интерфейсе и извлечь из бинарного файла.

## Демонстрация

1. Открыть приложение и дождаться статуса «В сети».
2. Нажать «+», выбрать небольшой тестовый документ.
3. Дождаться статуса «В сети» у файла.
4. В меню «⋯» выбрать «Сохранить на устройство» и открыть сохранённую копию.
5. Во вкладке «Сеть» показать пиры и переданный трафик.
6. Перезапустить приложение: библиотека и Peer ID сохраняются.

Если узел не подтвердил запись, файл остаётся «На устройстве».
Повторить отправку можно через меню «⋯». При отсутствии интернета это также
позволяет показать локальное шифрование и восстановление, но не сетевую реплику.

## Обмен с другом

1. Друг открывает «Получить» или «Сеть → Мой QR для получения файлов».
2. В меню файла выберите «Отправить другу» и отсканируйте его QR. Адрес также можно вставить вручную.
3. Дождитесь подтверждения доставки ключа. У друга появится входящий файл с кнопкой «Скачать».
4. После скачивания доступны «Открыть» и «Сохранить на устройство».

QR содержит Peer ID получателя. Ключ зашифрованного манифеста передаётся отдельным
зашифрованным сообщением, с проверкой подписи отправителя и подтверждением получателя.
Оба приложения должны быть открыты при передаче ключа. Если файл сохранён на другом
узле, отправитель может отключиться после доставки ключа: получатель скачает сетевую копию.
Для файла только на телефоне отправителя этот телефон должен оставаться в сети до конца скачивания.

Запрос ключа повторяется с тем же идентификатором до 24 секунд. Первая попытка
использует прямое соединение, последующие могут идти через надёжные TCP-соединения
с соседями. Повторное приглашение не создаёт вторую запись в библиотеке. Подтверждение
показывает, дошёл ключ напрямую или через ноду. Подключение к bootstrap само по себе
не подтверждает доступность конкретного получателя.

## Предпросмотр изображений

Нажатие на фото открывает просмотрщик: сначала небольшая миниатюра, затем оригинал.
Тонкая полоса отражает число полученных и проверенных частей файла; отдельной сетки
и искусственной задержки нет. Доступно увеличение жестом и сохранение оригинала.

При добавлении нового изображения создаётся JPEG не более 256 пикселей по длинной
стороне и 24 КиБ, без EXIF исходника. Миниатюра получает отдельный случайный ключ,
шифруется и реплицируется вместе с файлом. Ключ передаётся внутри защищённого приглашения.
Кэш миниатюр приватный, ограничен 4 МиБ. Полный расшифрованный файл удаляется после
декодирования; оригинальные зашифрованные блоки остаются в хранилище приложения.
Рендеринг ограничен 2048 пикселями по длинной стороне для экономии памяти, сохранение
восстанавливает исходный файл без изменения качества. У старых файлов миниатюры нет:
она появится при повторном добавлении изображения. Старые приглашения поддерживаются.

Автоматический direct upgrade и экспериментальный NAT traversal в ядре существуют,
но текущая Android-конфигурация их не включает. Наличие UDP-сессии не гарантирует
работающий путь через NAT. Отправка ключа предпочитает прямой путь при первой попытке
и сохраняет запасной маршрут через ноды.

Для загрузки и выдачи файлов транспорт подбирается автоматически с требованием
надёжной доставки блоков. Если у источника видна только UDP-сессия, приложение
открывает TCP-канал по сохранённому подписанному адресу либо использует надёжный
путь через соседей. Сам факт UDP-подключения больше не направляет блок 256 КиБ
в обычную UDP-датаграмму. Просмотр собственных фото может полностью работать
локально и сам по себе не подтверждает сетевую загрузку у получателя.

Адреса из подписанных дескрипторов других узлов сохраняются в приватном каталоге
приложения и используются при потере соединений и следующих запусках. Дубликаты
удаляются; кэш ограничен 128 узлами и 256 адресами, срок хранения — 30 дней.
Недоступность DNS первоначального bootstrap не мешает подключению к сохранённым узлам.

## Текущие границы

Узел живёт, пока жив процесс приложения; foreground-сервиса нет.
Во время загрузки приложение следует оставить открытым.
Одна подтверждённая реплика — факт записи, а не гарантия её будущей доступности.
Ключ манифеста хранится только в приватном индексе телефона. ID файла сам по себе
не даёт доступа к содержимому. Обмен ключом поддерживается через адрес получателя;
синхронизация папок, автоматическое восстановление реплик и удаление пока не реализованы.
«Сохранить на устройство» восстанавливает файл из локальных зашифрованных блоков.

## Проверки

Rust-тесты покрывают шифрование многоблочного файла и настоящую TCP-передачу между
двумя узлами: отсутствие пиров → локальный статус → повтор → подтверждение реплики →
восстановление с удалённого хранилища и побайтовое сравнение.
