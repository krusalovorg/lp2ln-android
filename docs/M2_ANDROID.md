# Проверка голоса LP2LN на двух телефонах

Этот preview для arm64 Android 10+ соединяет телефоны одним прямым QUIC Flow. Для теста достаточно точки доступа Wi-Fi. Удалённый сервер можно выключить. Звонки через промежуточные ноды пока недоступны.

## Первый звонок без компьютера

1. Установите LP2LN_Voice_arm64.apk из одного комплекта на оба телефона. Идентификатор приложения — lp2ln_android.krusalov.org.realtimepreview. Preview может обновить предыдущую тестовую сборку, подписанную тем же ключом. Основное приложение имеет другой идентификатор.
2. Подключите оба телефона к одному Wi-Fi без изоляции клиентов. Чтобы проверить автономность, отключите WAN точки доступа и мобильные данные на обоих телефонах. Для чистой проверки bootstrap подойдёт новый профиль Android с пустым кешем приложения. Установленный preview собирается с пустым bootstrap.
3. На обоих телефонах откройте приложение и разрешите уведомления для входящих вызовов. Имя можно изменить во вкладке «Профиль» после «Сети».
4. Откройте «Чаты», выберите собеседника и нажмите значок трубки в шапке переписки. Для первого вызова разрешите микрофон. Если пир ещё не появился, дождитесь LAN discovery и проверьте его Peer ID и QUIC endpoint в разделе «Сеть» → «Диагностика Flow».
5. На другом телефоне откроется экран входящего вызова. Если приложение свёрнуто, откройте уведомление. Нажмите «Принять» и разрешите микрофон. Для доступа к файлам во время разговора нажмите «Свернуть», для возврата — «Вернуться к звонку».
6. Проверьте речь в обе стороны, Mute и переключение динамика на каждом телефоне. Для проверки эха разведите телефоны по разным комнатам. Для длительного прогона включите «Диагностика звонка» на обоих концах.
7. Держите разговор минимум 20 минут. Пока идёт звонок, откройте обычную передачу файлов, передайте известный файл в обе стороны и сравните SHA-256 экспортированных копий. Зафиксируйте размер, длительность и результат. Сверните приложение, погасите экраны минимум на 5 минут, продолжайте говорить и проверьте слышимость после возврата. Проверьте входящий отказ, отмену до принятия, одновременный набор и повторный вызов после завершения.
8. Нажмите «Завершить». Проверьте оба экрана и индикаторы использования микрофона. Сохраните JSON с каждого телефона кнопкой «Сохранить отчёт звонка». Завершённая диагностика также лежит в files/last-call.json. Службу ожидания можно отключить отдельно. При потере пути текущий звонок завершится, после восстановления Wi-Fi можно позвонить заново.

Экран показывает RTT QUIC, вариацию интервалов поступления кадров, число принятых кадров, оценку пропусков последовательности, PLC, поздние кадры и underrun аудиоустройства. Оценка пропусков включает пропущенные у отправителя кадры. Битрейт вычисляется по байтам принятого Opus. Native heap относится к процессу Android. В диагностическом JSON процессорное время накопительное. Данные контрольной группы с отключённой диагностикой пригодны для оценки накладных расходов. Медиасодержимое не сохраняется.

## Проверка транспорта со встроенного экрана

Остановите службу голосового приёма. На обоих телефонах откройте «Проверка Flow без микрофона», укажите одинаковые длительность и PPS. На принимающем нажмите «Ждать тест», на втором «Запустить тест». Во время этого теста оставьте экран стенда открытым. Можно выбрать 10 секунд или 20 минут, 50 или 500 PPS. Каждый конец независимо проверяет номера и содержимое полученных датаграмм. «Сохранить JSON» экспортирует результат. Поле localAdmission содержит локально принятые отправки, remoteDelivered — проверенные приёмы на этом телефоне. Повторите для обратного направления установления соединения.

## Установка и инструментальный тест через ADB

Ниже команды для Bash. Подставьте серийные номера телефонов и используйте два терминала для длительных команд. Доступ к интернету во время теста не требуется.

~~~bash
adb devices -l
A=SERIAL_A
B=SERIAL_B
pkg=lp2ln_android.krusalov.org.realtimepreview
for dev in "$A" "$B"; do
  adb -s "$dev" install -r LP2LN_Voice_arm64.apk
  adb -s "$dev" install -r LP2LN_Voice_Device_Test.apk
  adb -s "$dev" shell getprop ro.build.version.sdk
  adb -s "$dev" shell getprop ro.product.model
done
runner="$pkg.test/androidx.test.runner.AndroidJUnitRunner"
case_name=lp2ln_android.krusalov.org.network.FlowDuplexDeviceTest
for dev in "$A" "$B"; do
  adb -s "$dev" shell am instrument -w -e class "$case_name" -e flowRole identity "$runner"
done
~~~

Скопируйте flowPeerId обоих инструментальных узлов. Их идентичности хранятся в отдельном каталоге и могут отличаться от идентичностей голоса. Приёмник B печатает новый flowPort во время запуска и ожидает A до 120 секунд. В примере B_IP и B_PORT принадлежат B.

~~~bash
adb -s "$B" shell am instrument -w -e class "$case_name" -e flowRole listener \
  -e flowPeer "$A_PEER" -e seconds 1200 -e pps 50 -e size 120 "$runner" | tee B-M1.txt

adb -s "$A" shell am instrument -w -e class "$case_name" -e flowRole dialer \
  -e flowPeer "$B_PEER" -e flowAddress "$B_IP:$B_PORT" \
  -e seconds 1200 -e pps 50 -e size 120 "$runner" | tee A-M1.txt
~~~

Для короткого smoke используйте seconds=4. Для интенсивного профиля задайте pps=500 на обоих телефонах. Размер size допускает 60, 120, 300 и 1000 байт в пределах MTU. Инструментальный запуск перезапускает процесс приложения. Выполняйте его отдельно от живого разговора.

Для сбора диагностики звонка подключите каждый телефон по USB. Сохраняйте только журналы голосового теста. Эти команды читают данные собственного debug-приложения. Снимите dumpsys meminfo до, во время и через минуту после звонка.

~~~bash
adb -s "$A" logcat -v threadtime -s LP2LNVoice:I > A-voice.log
adb -s "$B" logcat -v threadtime -s LP2LNVoice:I > B-voice.log
adb -s "$A" shell dumpsys meminfo "$pkg" > A-memory.txt
adb -s "$B" shell dumpsys meminfo "$pkg" > B-memory.txt
adb -s "$A" exec-out run-as "$pkg" cat files/last-call.json > A-call.json
adb -s "$B" exec-out run-as "$pkg" cat files/last-call.json > B-call.json
adb -s "$A" exec-out run-as "$pkg" cat files/flow-result.json > A-flow.json
adb -s "$B" exec-out run-as "$pkg" cat files/flow-result.json > B-flow.json
~~~

## Измерение mouth-to-ear

Используйте внешнее двухканальное устройство записи с общими часами. На канал 1 пишите опорный микрофон рядом с микрофоном A, на канал 2 — измерительный микрофон около динамика B. Исключите прямую акустическую связь между комнатами. Записывайте только синтетический сигнал. Для обратного направления поменяйте телефоны местами.

Сначала подайте один тестовый источник одновременно на оба измерительных канала, измерьте инструментальную задержку и разброс стенда. Затем воспроизведите probe.wav рядом с микрофоном A во время звонка. Начните запись до первого маркера и сохраните стерео PCM WAV 48 кГц, 16 бит. Подставьте измеренную поправку в миллисекундах. При идентичном сигнале и тракте калибровки поправка может быть нулевой.

~~~bash
python scripts/mouth_to_ear.py generate probe.wav --count 100
python scripts/mouth_to_ear.py measure recording.wav --expected 100 --correction-ms 0
~~~

Скрипту нужны NumPy и SciPy. Учитывайте количество неоднозначных и потерянных маркеров, геометрию микрофонов и разброс калибровки. Не принимайте процентиль по малой доле обнаружений за успешный тест. Сохраните исходный результат и погрешность для обоих направлений. Цель p95 ≤180 мс относится к этому акустическому измерению. RTT, возраст очереди и статистика Android измеряют другие интервалы.

## Сборка из локальных исходников

Разместите рабочие деревья lp2ln-realtime и lp2ln-android-locked рядом. Голосовой вариант имеет собственный rust-preview/Cargo.lock. Обычная сборка Android использует прежний опубликованный pin. Потребуются Rust 1.100.0, arm64 Android target, JDK 17, SDK 34, NDK 27.3.13750724, Cargo NDK и CMake. Для варианта arm64 соберите проверенный по SHA-256 статический libopus 1.6.1.

~~~bash
cd lp2ln-android-locked
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.3.13750724"
scripts/build-voice-opus.sh android "$PWD/build/voice-opus-arm64"
export OPUS_LIB_DIR="$PWD/build/voice-opus-arm64"
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest \
  -PvoicePreview=true -PrustAbis=arm64-v8a \
  -PapplicationIdOverride=lp2ln_android.krusalov.org.realtimepreview
~~~

Для Linux доступен проверочный путь без Cargo NDK. Из дерева Android выполните scripts/build-voice-apk.sh. Скрипт собирает arm64 JNI закреплённым Cargo, добавляет его в APK и запускает Kotlin unit-тесты. APK появятся в app/build/outputs/apk/debug и app/build/outputs/apk/androidTest/debug.

Сборка по умолчанию использует локальную debug-подпись Android. Телефоны принимают обновление существующего приложения только с совместимой подписью. При конфликте подписи сохраните нужные данные до выбора нового профиля или переустановки. Для воспроизведения теста RTC на Linux соберите host-вариант libopus тем же скриптом и укажите его prefix через OPUS_LIB_DIR, OPUS_NO_PKG=1 и OPUS_STATIC=1 при cargo test --locked --release -p lp2ln-rtc.

## Что прислать после прогона

Модели телефонов и Android, SHA-256 APK, результат LAN discovery и ручного соединения, длительность слышимого разговора, время выключения экрана, хеши переданного файла, JSON обоих концов, измерения памяти, результаты акустической задержки и замечания про эхо. Для допуска M3 сначала подтвердите M2 на двух физических телефонах. Прямая версия завершает Flow при смене адреса. Relay и миграция потребуют отдельной реализации и проверки сквозной конфиденциальности.

Для проверки JNI на Linux без Android-аудиоустройств соберите rust-preview как host cdylib с host-префиксом Opus и выполните scripts/test-voice-jni.sh /absolute/path/to/liblp2ln_android.so. Стенд поднимает два JVM-процесса, проверяет запрет раннего старта медиа, синтетический PCM в обе стороны, ротацию и завершение с подтверждением.
