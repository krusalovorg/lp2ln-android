# Замеры передачи файлов

База — `14f3d3c` из `feature/lp2ln-integration`. Скрипт извлекает её через `git archive`, добавляет таймер последнего PushAck и подключает тот же стенд. Исходная отправка и скачивание при этом сохраняют свои алгоритмы.

```sh
python docs/file-transfer/run.py --output /path/to/results.json
```

Нужны Git, Python 3.9+ и Rust с зависимостями из `rust/Cargo.lock`. Параметр `--offline` работает с заполненным кэшем Cargo. В сборке тестов используются `opt-level=2` и `debug=0`. Промежуточные сборки и полные логи лежат в игнорируемом `rust/target`. Отчёт содержит только параметры сценариев, времена, счётчики и результаты проверок.

## Условия

- Отправитель, узел хранения и получатель работают в отдельных средах Tokio на одном компьютере с Windows. Используются TCP через loopback, шифрование, штатные блоки по 256 КиБ и независимые файловые хранилища. Узел хранения добавляет 25 мс к обработке каждого запроса. Соединения установлены до замера.
- В основном сценарии перед каждым повтором создаются новые файл и каталоги всех участников. У получателя проверяется отсутствие каждого блока и манифеста. Для размеров 1, 8 и 32 МиБ выполняются по пять повторов базы и окна 4. Окна 1 и 2 сравниваются на 8 МиБ с пятью повторами каждое.
- Время до PushAck начинается после импорта и заканчивается, когда все ответы `stored=true` получены от одного узла. Время до `uploaded` включает отправку объявлений DHT и запись статуса в локальный индекс. Разница двух отметок показывает стоимость этого этапа вместе с записью индекса.
- Скачивание включает получение и расшифровку манифеста, получение блоков, проверку их хешей, расшифровку и запись. Экспорт и сравнение SHA-256 выполняются после остановки таймера. Скорость — размер исходного файла в МиБ, делённый на медиану времени успешных запусков.
- В отдельных прогонах на 1 МиБ останавливается отправитель, указанный первым в списке источников. Ещё два сценария моделируют предпочтительный узел, который задерживает ответы на 1,2 с или вообще их не отправляет. В каждом случае доступный узел имеет весь файл. Тест повтора ограничивает число сохраняемых блоков на первом запуске и поднимает узел с тем же диском без ограничения для повторной отправки.

## Размещение

Основной замер использует одну удалённую полную копию. В прежнем прогоне для 8 МиБ медиана была 10,20 с с одного узла и 9,63 с двух узлов на одном физическом сервере. Новый отдельный тест на двух непересекающихся наборах блоков подтвердил совпадение SHA-256 при двух доступных узлах. При отключении любого узла получатель с пустым кэшем завершал скачивание ошибкой. Полная реплика позволяет восстановить файл при отключённом отправителе, пока узел с этой копией доступен.
